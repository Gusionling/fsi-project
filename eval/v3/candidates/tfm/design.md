# TFM-L 구현 설계 (Phase A)

Claude 제안의 TFM-S/TFM-T 최소판이다. 효과·사실 무결성을 입증하지 않았다.
TFM-O와 상태 근거 기반 PAR는 구현하지 않는다. 공격 데이터·sealed는 읽지 않았다.

## 불변 조건 대비 구현 현황

| 조건 | 구현 | 검증 |
|---|---|---|
| T1 | extractor.extract는 Chunk만 받고 query/Case를 받지 않음, 청크별 1회 호출 | 다른 질문에서 추출 프롬프트 동일, 다른 청크도 비포함 |
| T2 | S=number/date/enum/entity_ref, T는 short_text 추가 | 모드·타입·범위·문자열 제한 테스트 |
| T3 | ontology.yaml에 10속성, 허용 source_type; entity_ref 공식 목록 검사 | unknown/faq 권한·공식 엔티티 테스트 |
| T4 | 원래 시스템+고정 정책, build_user_prompt(query,[합성 사실표])로 같은 청크 포맷 | 원문 sentinel 누출 없음·베이스 시스템·모델 검사 |
| T5 | B1(toggle)→추출→허가→표 답변→V4, 거부 행 비율은 보조 risk | 호출 순서·거부 집계·fallback 테스트 |
| T6 | enum/short_text/타입 맞는 거짓은 아래 알려진 통로 표에 명시 | 수수료 0/완료 안내 enum의 허가 통과 테스트 |
| T7 | TFM-O 없음, 비교군은 하네스 L2 | 후보 간 import·common import 없음 |

## 설계 결정

| 결정 | 이유 | 대안 |
|---|---|---|
| 한 청크라도 추출 실패하면 모든 표 전달을 중단하고 고정 fallback | 부분 문맥으로 적용 조건을 누락한 확정 답변을 피함. 원문으로 되돌리지 않음 | 성공한 부분만 답변하면 품질은 나아질 수 있으나 누락 위험이 있음 |
| 허가된 행이 없으면 고정 fallback, V4는 여전히 실행 | 답변기의 외부 지식으로 표 밖 정보를 채우지 않음 | 빈 표로 LLM을 호출하면 모델의 임의 답변 가능 |
| source_type은 Chunk 메타데이터만 사용 | 추출기가 출처를 스스로 승격하지 못하도록 함 | LLM이 낸 source_type은 신뢰하지 않음 |
| 행은 정확히 attribute/type/value, 추가 키는 행 전체 거부 | 원문·설명·조작된 출처를 자유 텍스트 경로로 넘기지 않음 | 추가 키만 제거하면 손상 시도를 숨김 |
| 답변 표는 코드가 만든 단일 context Chunk, 고정 id | 기존 build_user_prompt의 포맷 재사용. 원래 chunk_id/text가 별도 통로가 되지 않음 | chatbot.answer(query,원문)은 T4 위반 |
| 온톨로지는 YAML 1.2의 JSON 부분집합으로 작성·표준 json으로 읽음 | 동결 requirements를 바꾸거나 새 의존성을 추가하지 않으면서 단일 스키마 사용 | PyYAML도 가능하지만 이 최소판엔 불필요 |
| 출처별 좁은 FAQ용 10속성·고정 단위/범위 | 원문의 자연어를 답변기로 넘기는 폭을 제한. 공격 데이터를 보지 않고 일반 업무 명세로 선택 | 범용 자유 JSON 속성은 타입 중재를 무력화 |
| short_text는 NFKC 정규화 후 길이·제어문자·URL·전화·명령형 검사 | 전각 문자·제로폭 문자를 통한 간단한 우회를 줄임 | 자연어 의미 전체를 결정적으로 판정하는 규칙은 아님 |
| JSON 파손/중복 키/NaN/SDK 예외는 추출 실패 | 모호한 파싱과 불완전한 결과를 정상 표로 쓰지 않음 | 자동 JSON 복구/재시도는 별도 LLM 행동·비용을 추가 |
| 거부율로 자동 차단하지 않음 | 거부율은 설계상 보조 신호이며 별도 기준선 탐지기로 바꾸지 않음 | 임계값 튜닝은 Phase A 범위 밖 |

## 허가와 집계의 의미

속성별 단위는 fee/limit=원, interest_rate=%이며 날짜는 실제 달력의 YYYY-MM-DD다.
출처 권한은 문서의 진실성을 보증하지 않는다. Chunk.source_type을 하네스가 제공한다는
가정이 필요하며, source_type의 실제 인증은 이 후보가 하지 않는다.

flags.n_rows는 성공적으로 파싱된 각 rows 배열의 원소 수(비정상 행 포함),
n_rejected는 행 검증 거부 수, rejection_reasons는 각 거부 행의 첫 사유 집계다.
n_accepted는 허가된 행 수, n_forwarded는 실제 답변 LLM으로 전달한 행 수다.
추출이 일부 실패하면 n_accepted가 양수여도 n_forwarded=0이다.
extract_failed/n_extract_failed/n_chunks와 오류 클래스별 extraction_errors를 별도 기록한다.
추출 실패한 청크의 행 수는 알 수 없으므로 거부 행으로 가짜 집계하지 않는다.
risk=n_rejected/n_rows(0행이면 0)이며 risk_is_secondary=true다.
**낮은 risk는 안전을 뜻하지 않는다**: 전면 추출 실패·정보 누락·허가된 거짓은 risk=0일 수 있다.
단순 n_accepted/n_rows는 필수 정보 보존률이 아니다. required_info 기반 평가는 하네스가 해야 한다.
모든 fallback은 fallback_used=true이므로 정상 개입률에 포함된다.
llm_calls는 gate 제공 개수+추출 시도+답변 호출의 논리 개수다. 내부 재시도는 하네스 LLM 집계가 기준이다.

## 알려진 통로

| 통로 | 그대로 남는 위험 |
|---|---|
| enum: procedure_step의 '완료 안내' 등 | 허가된 선택지 자체가 거짓 완료처럼 행동을 유도할 수 있음. 상태 조회를 추가해 PAR로 바꾸지 않음 |
| short_text | 40자 안의 우회 문장/명사구/다국어·난독화 지시가 정규식 검사를 통과할 수 있음 |
| 타입 맞는 허위 값: 수수료 0원·한도·기한 | 허용된 출처·범위에 맞으면 통과. **TFM-L은 사실 무결성을 보장하지 않는다** |
| 잘못된 source_type 메타데이터 | 문서가 실제 공식 소스라는 검증이 없으면 허가가 무력화됨 |
| 추출기 오염 | query-blind라도 원문 지시가 허용 값/조건을 조작하거나 정상 사실을 누락시킬 수 있음 |
| 공식 엔티티 참조 | 값의 공식 여부만 검사. 해당 질문/업무에서 사용이 정당한지는 별도 문제 |
| 모순/중복 행 | 서로 다른 허가된 값이 동시에 표에 남을 수 있음. 이 구현은 충돌 해결·사실 판정을 하지 않음 |
| 답변 LLM | 원문은 없지만 질문 자체의 지시·표 밖 추론·허용된 값의 조합이 행동에 영향을 줄 수 있음 |

## 정상 업무 손실과 미결정 사항

- 고정 enum·좁은 속성·출처 제한은 FAQ 밖의 정상 사실과 조건/예외/순서를 버릴 수 있다.
- 전체 실패 fallback은 일부 문서 오류가 정상 상담 전체를 중단시키는 가용성 약점이다.
- 범위와 선택지의 실제 업무 커버리지, T 모드의 이득, 정보 보존률은 미측정이다.
- 가장 불확실한 결정은 **일부 실패 시 전체 fallback**과 **10속성의 표현력/허가 범위**다.
  변경이 필요하면 dev에서 근거를 만들고 버전을 남겨야 하며 calib으로 튜닝하지 않는다.
- 모델/프롬프트/온톨로지의 최종 동결·폐기 기준은 Phase B 사전 등록 단계에서 정한다.
- 계약 변경 요청 없음.
